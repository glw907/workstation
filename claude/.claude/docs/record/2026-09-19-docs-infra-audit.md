# Audit: the workstation's documentation-writing Claude infrastructure vs published practice (2026-09-19)

## 1. Verdict

Broadly current, and on several axes ahead of what anyone publishes. The register system, the charter's audience→standard→linter→exemplar mapping, the Vale layering, the hook output contract, and the always-on output style all match current primary guidance; nothing in the inventory is built on a retired mechanism. Three findings matter. First, **the always-loaded context files are over every budget that governs them**: `~/.claude/CLAUDE.md` is 399 lines (~6,520 est. tokens) and `cairn-cms/CLAUDE.md` 364 lines (~6,377), against Anthropic's current "under 200 lines" target and the workstation's own 6,000-token `claude-context-budget` ceiling, which both now exceed; neither uses `@` imports or the newer path-scoped `.claude/rules/`. Second, **the docs-register measure profile is dead on arrival**: `~/Projects/cairn-cms/.tellgrader.json` was never created (the 2026-09-08 handoff named it as obligation 1), so the `measures` object that five register files, `prose-voice-reviewer`, and `diff-reviewer` all give instructions about can never appear; I confirmed with a live `tellgrader` run on `docs/why-cairn.md` that the report carries no `profile` or `measures` key. Third, **the Vale layer has quietly aged**: the vendored Google package carries 31 rules against 36 in the current hub release (last touched 2026-06-23, no version recorded), CI pins Vale 3.15.1 while the workstation runs 3.21.0 and upstream is 3.22.0, and Google's own style guide is revised roughly monthly with a dated changelog that nothing on this machine watches.

## 3. Ahead of published practice, or deliberately different with a recorded reason

- **Diátaxis kept as a private classifier and never cited on a page.** Standing ruling, Geoff 2026-08-14, recorded at `docs/internal/docs-register.md:65` and reasoned in `docs/internal/record/2026-09-08-polish-inputs/proposal-research-structure.md` (which cites diataxis.fr/compass). This matches Diátaxis's own "compass, not taxonomy" framing; do not undo it. The four **audience** tracks with vocabulary contracts, arrival states, success criteria and counterpart questions go beyond anything Google, Microsoft or Diátaxis publishes, and Diátaxis explicitly does not do an audience split.
- **"A floor is not a ceiling"** plus the evidenced-and-recorded deviation procedure, and the "When a Vale finding is wrong" section with its markup-vs-scoped-suppression worked examples. Vale's own docs carry nothing equivalent.
- **The visual layer** (alt mandatory and capped at 150 chars, kind-first alt, mermaid `accTitle:`/`accDescr:`, the two-part alternative, the ~15-node budget, WCAG 1.4.10's reflow exemption cited by name, ruling 2026-08-15) exceeds Google's accessibility page (last revised 2025-04-21).
- **The facts container** with tagged provenance and `check:facts`, plus reference gating (`check:reference`, `:signatures`, `:snippets`, `:readiness`): single-sourcing and drift control well past the Write the Docs docs-as-code page.
- **`tellgrader`**: an evidence-grounded AI-tell scanner with a written `MEASURES.md` and report-only measures. No published Vale package detects AI-writing tells; the nearest hub entries are `alex` and `neighbor`, which do inclusive-language and ableist idiom only.
- **`skills/writing-voice/evals/evals.json`** is a skill-creator-shaped eval corpus with a baseline comparison, built before `claude plugin eval` shipped. (Its description still names `tell-grader.py`, which the Go `tellgrader` replaced.)
- **`cairn-cms/scripts/checks/check-skill-budget.mjs`**, a 3,500-token hard gate on a shipped SKILL.md plus a tier-map-vs-registry check. Anthropic publishes only a prose "under 500 lines".
- **Hooks are already on the current contract**: `hookSpecificOutput`/`hookEventName`/`additionalContext`, exit 2 with stderr for the error tier, fail-open, changed-line scoping, `Write|Edit` as a valid pipe matcher. Nothing to change.
- **The always-on output style is the right mechanism and is not deprecated.** The current output-styles doc positions it alongside CLAUDE.md, skills and agents in a comparison table, and says CLAUDE.md is for project context, not tone or format. `keep-coding-instructions: true` is a live field.
- **The em-dash ban in code comments** is a house rule the standards are silent on, and is recorded as such in the charter, the output style and `eslint.config.js`. Google still recommends the em dash, unspaced (dashes page, 2024-10-15).

## 4. Deprecated or at risk

- **Slash commands** are documented as deprecated in favour of skills. The infrastructure barely uses them; only the two vestigial references above.
- **`docs.anthropic.com` → `code.claude.com`.** Every Claude Code URL in the inventory 301-redirects.
- **The Write the Docs docs-as-code page is effectively unmaintained** (its talk list stops at 2022, no dated updates, no successor page). Nothing here cites it, which is correct; don't add it as a live source.
- **The Microsoft standard is aging.** The bias-free communication page's last substantive edit reads 2024-04-18 while Google revises monthly. The editors arm's floor will drift behind Google's; watch it rather than act now.
- **TSDoc is still formally "a proposal to standardize,"** never ratified. Standing risk for the TypeScript arm, not an action. `eslint-plugin-tsdoc` is actively maintained (ESLint 10 compatibility, 2026-02-25) and the repo is current at 0.5.2 under ESLint 10.9.0.
- **Vale's vendored `meta.json` feeds still point at `errata-ai/*`** while the upstream repo appears to have moved to `vale-cli/*`; a future `vale sync` may follow a stale feed.
- Google's own guidance has **no AI-generated-content or writing-for-AI section**; the AI pages on developers.google.com are Search Central SEO policy. Do not treat them as authoring guidance.
