---
name: svelte-check
description: >-
  Run svelte-check type checking for this SvelteKit project. Use after writing or modifying any
  .svelte, .ts, or .md (mdsvex) file, after installing packages, changing tsconfig.json, or
  updating svelte.config.js, and on requests like "check for errors", "does this compile", or "run
  type check". Scope: a repo whose root package.json has a check script, not one whose web app is a
  subdirectory under a non-Node gate.
---

Run `npm run check` from the project root and interpret the results.

## Steps

1. Read the repo's own `check` script in `package.json` before running it. Some repos run
   `svelte-check` alone; others chain further legs after it, such as `npm run lint:openapi`
   or `npm run check:docs-links`. Then run the check:

```bash
npm run check
```

This runs `svelte-check --tsconfig ./tsconfig.json` across all `.svelte`, `.ts`, and `.md` (mdsvex) files.

2. Interpret the output of whatever legs the script runs:

- **Clean:** the line `svelte-check found 0 errors and 0 warnings` is the svelte-check leg's own
  clean marker. A repo whose `check` script has further legs is clean only when every leg is
  clean. Report success and proceed.
- **Errors:** list each error with its file path and line number. Do not mark work complete until all errors are resolved.
- **Warnings only:** report them but don't block progress. Warnings are informational.

3. If there are errors, fix them before committing. Re-run after fixing to confirm clean.

## Notes

- `cloudflare:email` type errors may appear if `@cloudflare/workers-types` isn't installed or `tsconfig.json` doesn't include it under `"types"`. Fix: `npm install --save-dev @cloudflare/workers-types` and add `"types": ["@cloudflare/workers-types"]` to `compilerOptions`.
- mdsvex `.md` files used as routes (e.g. `+page.md`) are checked like Svelte components. `$props()` and imported components must be typed correctly.
- The `.svelte-kit/tsconfig.json` that `tsconfig.json` extends is generated by SvelteKit. Some repos already prefix `svelte-kit sync` in their `check` script, so a missing `.svelte-kit/tsconfig.json` is the symptom to look for rather than a step to add blindly. If it's missing, run `npx svelte-kit sync` first.
