## Queries met in full with the skill off

Case 2 is met in full with the skill off on Sonnet (`2-sonnet-off`) and Opus (`2-opus-off`), so on those models it doesn't separate on from off. Both off answers reached the backstop through `site-pass`. They differ from the skill in one way the behaviors don't test: they also write the consultation line into the approved spec's header, where the skill has the session record only the line it would add. On Haiku, case 2 separates only partly: 2 of 3 met in both states.

Case 4 is met in full with the skill off on all three models. That is expected for the out-of-scope query, which tests only that the skill stays unloaded.

## Behaviors missed with the skill on

`2-haiku-on`, behavior 3. The answer says the skill doesn't settle whether the build pauses for a verdict, "so that call would need to come from Geoff or from the spec's own rules." It also says the spec-writing session, not the task session, runs the triage. Together these leave the background task session waiting on Geoff or another session, not running the backstop through to its build.
