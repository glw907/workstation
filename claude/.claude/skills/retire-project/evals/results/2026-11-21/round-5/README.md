Case 4 is the only query whose behaviors are all met with the skill off, on all three models. That's by design: its one behavior is that the skill stays unloaded, so it doesn't separate on from off. No in-scope query is fully met with the skill off. Case 3 separates most sharply, at 0 of 3 off on every model.

No behavior was missed with the skill on.

Two load notes. Every in-scope load came from the slash command's expansion (`"slashExpanded": true`), not a Skill call. `1-opus-on` and `3-haiku-on` also called the `writing-voice` skill, and `2-opus-off` called `runbook`. Neither of those is retire-project, so none changes a load verdict.

No session used a write tool. The tools used were Glob, Grep, Read, and Skill, and several sessions report that a read of `~/.claude/docs` or `~/Projects` was refused. No answer claims to have changed a server, mailbox, vault, account, or repo.
