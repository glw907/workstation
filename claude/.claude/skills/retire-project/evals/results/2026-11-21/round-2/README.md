## Queries that don't separate on from off

Case 1 is fully met with the skill off on Sonnet (`1-sonnet-off`) and Opus (`1-opus-off`). Without the skill, both still back up first, take the domain off before the Worker, and gate each delete on Geoff's go-ahead. Case 1 therefore doesn't separate on those two models. It separates on Haiku only: `1-haiku-off` removes the DNS record after the Worker. Case 4 is met with the skill off on every model by design. Its one behavior is that the skill stays unloaded.

## Behaviors missed with the skill on

`2-haiku-on`, behavior 3. The answer describes the lapse path correctly as option B ("auto-renew off, parked until expiry"), but it recommends option A, "Park and keep renewing", for a domain the query says nothing uses. The skill lets a no-use domain lapse, so the recommendation inverts the behavior instead of carrying it out.

No session with the skill on or off used a write tool. Every `toolsUsed` list holds only Read, Grep, Glob, or Skill, and several of those reads were refused by the permission prompt.
