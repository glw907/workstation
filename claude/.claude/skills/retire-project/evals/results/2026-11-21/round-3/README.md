Case 1 on Opus meets every behavior with the skill off, so that query does not separate on from off on Opus. Haiku and Sonnet each miss behavior 3 with the skill off, because their dry runs give no id for the D1 database or the domain. Case 4 meets its one behavior in every session, on and off, as an out-of-scope case should.

One behavior is missed with the skill on. In `2-sonnet-on`, behavior 2 of case 2 asks for a kept domain to be parked with `MX 0 .`, `v=spf1 -all`, and `v=DMARC1; p=reject;` at the apex, and Email Routing off. The answer gives every one of those records for the domain while it lapses. It never says what a kept domain gets. On keeping, it says only that renewing "applies only if you name a use for the domain". The skill's step 4.4 ends "and a kept domain gets the same", a clause the Haiku and Opus answers both carry.

No session used a write tool, and every answer says it changed nothing.
