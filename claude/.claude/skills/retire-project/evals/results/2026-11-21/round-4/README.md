One in-scope session met every behavior with the skill off: `1-sonnet-off` met all three behaviors of case 1, so on Sonnet that query does not separate the skill on from off. Case 1 still separates on Haiku and Opus, and cases 2 and 3 separate on every model. Case 4 is met with the skill off on every model by design, since its one behavior is that the skill stays unloaded.

One behavior was missed with the skill on. In `2-opus-on`, behavior 1 of case 2 is missed because the answer states the outcome as settled by the skill ("This skill doesn't treat that as one of two options") and never says the domain's fate is Geoff's call. A reader could take "it only gets renewed if you name a use for it" and the closing recommendations as handing him the decision, so this is the closest call in the round, but the answer does not state it. The other two models carry it in plain words: "The lapse is still your call" in `2-haiku-on` and "Your call:" in `2-sonnet-on`.

No session wrote a file or changed a live system. The tools used were Read, Grep, Glob, and Skill, and several reads of `~/.claude/docs` and `~/Projects` were denied by permission prompts.
