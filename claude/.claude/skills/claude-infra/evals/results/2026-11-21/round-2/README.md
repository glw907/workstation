## Queries met in full with the skill off

Only case 4, the out-of-scope query, is met in full with the skill off, on all three models. That is expected, since its one behavior is answering without the skill. No in-scope query is met in full with the skill off on any model, so cases 1 to 3 all separate on from off.

## Behaviors missed with the skill on

- `2-haiku-on`, load: the skill was listed but not invoked, so the load requirement fails for case 2 on Haiku.
- `1-haiku-on`, behavior 2: it says a workstation skill gets an entry in a manifest in `claude-tooling.md`, which contradicts a skill authored here being its own manifest, and it runs `claude-tooling-sync verify` only for the dotfiles case.
- `2-haiku-on`, behavior 2: it cites no Anthropic page for the hook choice. The skill never loaded.
- `2-haiku-on`, behavior 3: it never says CLAUDE.md carries only a fact that applies every turn, and it suggests a CLAUDE.md line as a courtesy. The skill never loaded.
- `2-sonnet-on`, behavior 3: it gives only the "nothing enforces it" half of the CLAUDE.md reason and leaves out that CLAUDE.md carries only a fact that applies every turn.

No session used a write tool, and every in-scope answer says it changed nothing.
