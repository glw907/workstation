No in-scope query had all its behaviors met with the skill off. Case 4, the out-of-scope query, was fully met with the skill off on every model, as expected, since its one behavior is a plain answer without the skill.

Two behaviors were missed with the skill on, both behavior 3 of case 2. In `2-sonnet-on` and `2-opus-on`, the answer rules out CLAUDE.md because a rule there "is only a request" that nothing enforces, but it never states that CLAUDE.md carries only a fact that applies every turn. That is the half of step 2 in SKILL.md the behavior asks for, and `2-haiku-on` is the only answer that gives it.

In case 1, `1-haiku-on` and `1-opus-on` say a skill authored here needs no manifest entry without naming its directory as the record. That carries the meaning of behavior 2, so both count as met. In `1-haiku-off` and `1-sonnet-off`, the answer places the checklist in a skill but gives a fit reason rather than the sometimes-needed reason behavior 1 names, so both count as missed.

No session wrote a file or ran a write tool. Every `toolsUsed` list holds only Read, Glob, Grep, and Skill, and every in-scope answer says it changed nothing. Several sessions report that reads of `~/.claude`, `~/.dotfiles`, or `~/Projects` were denied, which were read attempts only.
