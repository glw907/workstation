## Queries met in full with the skill off

Case 4 meets its one behavior with the skill off on all three models. It is the out-of-scope control, so on and off give the same answer by design, and the query doesn't separate them. No in-scope query was met in full with the skill off. With the skill off, cases 1 and 2 met only behavior 1 on every model, and case 3 met none.

## Behaviors missed with the skill on

- `1-haiku-on`, behavior 2. The answer runs `claude-tooling-sync verify` and keeps one home, but it says only "record it in its manifest" and never says what records the skill: an authored skill is its own manifest, its directory.
- `2-haiku-on`, behavior 3. The answer rejects CLAUDE.md because "nothing enforces it", but it leaves out the other half, that CLAUDE.md carries only a fact that applies every turn.

## Changes to real systems

No session changed a server, mailbox, vault, account, or repo. No `toolsUsed` list holds a write tool, and every in-scope answer says nothing was changed or plans without editing. Several sessions tried to read `~/.claude` or `~/Projects` and were denied, and they report the denial as a limit on the answer.
