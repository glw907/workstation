A hedge such as "most likely" counted as met when the answer still gave the hedged claim as its conclusion, as in `2-haiku-on` behavior 1 and `1-opus-off` behavior 1. It counted as missed when the answer set the claim beside an equal alternative or made it conditional, as in `2-haiku-off` and `3-opus-off`.

Case 4 is the only query whose behaviors are all met with the skill off, on every model. That is expected for the out-of-scope case, and it means case 4 does not separate on from off. Each in-scope query separates on from off on every model.

Behaviors missed with the skill on:

- `1-haiku-on`, behavior 2. The title "907-life Resend API key" puts the scope first, and the answer moves scope out of the title into the note, which contradicts the system, secret, scope order.
- `2-haiku-on`, behavior 2. The session never loaded the skill, and its answer gives no 25-minute wait and no 150-second spacing, only "stop reading items for a while".

The `2-haiku-on` session also fails the load half of the rule: the skill was listed, but `invoked`, `readSkillFile`, and `loadedFrom` are all empty.
