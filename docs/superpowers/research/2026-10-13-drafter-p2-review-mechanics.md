## Findings

1. Blocker, correctness. :182, :89, :192-193. Retrying non-idempotent calls inside the client can double-spend: a reset on `Create` after the body was sent can leave a created batch; a mid-stream `Send` reset is billed and the retry bills again; neither attempt gets an intent or ledger line (spec :790), and it bypasses resume's `List` adoption. Fold: retry in place only idempotent calls (`Get`, `Results`, `List`, `CountTokens`, the workspace probe); on `Create` and `Send` retry only when the request provably never left (dial or DNS failure, 429); an ambiguous failure returns a distinct sentinel (`ErrMaybeSent`, or `ErrTransport` with that meaning) so pass 5 adopts via `List` or settles sync `estimated`. Rows: reset after the `Create` body is read gives one request and that error; same for `Send` mid-stream.
2. Major, correctness. :187-188. The env-isolation test passes without the option: with `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL` all set, a client without `WithoutEnvironmentDefaults` sends the same as the isolated one (explicit `WithAPIKey` overwrites `X-Api-Key`, `WithBaseURL` wins, `DefaultClientOptions` returns at the API-key branch). With `ANTHROPIC_AUTH_TOKEN` alone, the default client leaks `Authorization: Bearer SENTINEL_TOKEN`. Fold: one row per variable set alone, plus `ANTHROPIC_PROFILE` and `ANTHROPIC_CUSTOM_HEADERS`; assert no header contains any sentinel and `Authorization` is absent.
3. Major, correctness. :79-81, :190-191 (pass 5 consumes). The workspace check is unenforced and its test can't fail: "no `Create` after it" holds only if the test stops calling; P2.1 defers the spec's row to P2.3 and P5.2 omits it; the "one free call" is unnamed. Fold: (a) spending and counting methods error until `CheckWorkspace` passed; test calls `Create` after a failed check and asserts zero hits; (b) the free call is `GET /v1/models?limit=1`; (c) `Options.WorkspaceID` sent on every request via `option.WithHeader("anthropic-workspace-id", …)` (SDK `messagebatch.go:868-873`: "if sent, it must match that Workspace"; probe confirmed a client-wide header reaches every call); (d) an absent response header is a mismatch.
4. Major, correctness. :87-88, :90-95, :193-194. Spend-limit detection misses documented shapes: the tier-cap 429 is `rate_limit_error` with `error.details.error_code == "enforced_spend_limit_reached"` and no `retry-after`; the SDK doesn't expose `details`, parse it from `(*anthropic.Error).RawJSON()` (probe confirmed). The org-level limit is a 400 starting "You have reached your specified API usage limits", which the plan's workspace wording misses, escalating every page. A batch `errored` result carrying the limit message is classified escalate (batches can overshoot). A 429 with neither `retry-after` nor the code has no action. Fold: match the prefix "You have reached your specified" plus `details.error_code`; a spend-limit action for errored results; name the bare-429 action; a row each.
5. Major, correctness. :75-77, :90-95, :192-197. Unhandled states: 500 or 529 on `Create`, `Get`, `Results`, `List`, `CountTokens` matches no row (one 529 on a poll stops the run); mid-stream errors after a 200 (the SDK's `ssestream` turns `event: error` into an API error) are missed by status classification; `stop_reason` `model_context_window_exceeded` and `pause_turn` (`message.go:11989-11995`) are unmapped. Fold: retry idempotent calls on 5xx/529 within `WallTime`; classify sync failures by error type; map unknown stop reasons to the `max_tokens` action or escalate; a row each.
6. Major, correctness. :63-67, :86. One timeout bounds a whole stream: `WithRequestTimeout` is a per-attempt context whose cancel `Execute` hands to `bodyWithTimeout` (`internal/requestconfig/requestconfig.go:546-563, 630-638`), so it caps an entire `Send` stream and `Results` download. Fold: short `RequestTimeout` for unary calls, long `StreamTimeout` for `Send` and `Results`, passed per call; a row with a slow `httptest` stream.
7. Major, correctness. :99-121, :152-173. Ledger line format and file states unspecified: `Entry` has no timestamp though `Spend(since, until)`, the cycle total, and P2.4's "23:59 UTC" row need one; fixtures need a named format; absent, empty, or malformed (torn last line) states undefined, and skipping a malformed line undercounts. Fold: name the line schema with `time` RFC 3339 UTC, stamped under the lock from an injectable clock; absent or empty reads as zero; first append creates the dir 0700; a malformed line is an error naming file and line (fail closed in `Reserve`, `Settle`, `Spend`); one `write` per line on `O_APPEND`; a row each.
8. Major, correctness. :162-164. The two-process proof can pass without the lock (microsecond window). Fold: a test-only pause between check and append (child env flag or unexported hook); state that the lock-free twin fails.
9. Major, correctness. :223-232, P5.6. The smoke is likely to fail after spending: Haiku 5.5 "Thinking is on by default and counts toward `max_tokens`", so small `max_tokens` at production efforts hits `max_tokens`; `go test` panics at its default 10m `-timeout`; an aborted smoke leaves worst-case reservations until reset; structured outputs require `additionalProperties: false` or 400. Fold: `max_tokens` about 4096 per shape; `go test -tags smoke -count=1 -timeout 90m -run Smoke ./internal/batch/`; a `t.Cleanup` that settles unsent intents `void` and cancels an open batch; synthetic schemas carry `additionalProperties: false`.
