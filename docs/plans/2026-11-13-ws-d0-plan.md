## What changes

`session_hit` in `bin/.local/bin/claude-worktree-busy` skips a `claude agents --json` row whose
`pid` is the check's own process or one of its ancestors. `ancestors()` already computes that set
for `process_hit`. Nothing else in the script changes: the contract (exit 0 and no output when
free, exit 1 and one line when busy, exit 2 on a usage error), the three checks, and their order
stay. The module docstring's sentence on what the session check skips names the new skip. A row
with no `pid`, or a `pid` outside the chain, counts as it does today.

Out of scope: the wording in `conductor.md`, `round-run.md`, `CLAUDE.md`, and STATUS about the
check (pass D2 and D3 own those files), and any change to the process or edit checks.

## Tasks

### T1. Two failing test cases (10 minutes, `runner`)

Outcome: `tests/claude-worktree-busy.test.sh` has the two cases, and both fail on today's script.

Files: `tests/claude-worktree-busy.test.sh`.

The stub `claude` gains an optional first row for the caller. When `STUB_SELF_PID` is set it
prints, before the existing row, a row shaped like the existing background row with `"pid":
${STUB_SELF_PID}`, its own id (such as `self0000`), `"state": "working"`, and cwd
`${STUB_SELF_CWD}`. The caller's row must come first, so today's script hits it before the other
row. The test passes `STUB_SELF_PID="$$"`: `$$` is the test's top-level shell, and the script runs
under it inside `check`'s command substitution, so the pid is in the script's ancestor chain
(Mechanism M3).

- Case A, "caller's own row in the path": `STUB_SELF_PID="$$" STUB_SELF_CWD="$repo"`, the other
  row's cwd left at its default `/nowhere`; want exit 0 and no output.
- Case B, "caller's row and another session in the path": the same, with `STUB_CWD="$repo"`; want
  exit 1 and the message prefix `busy: claude session aaaa1111`.

Place both cases with the other session cases (test lines 127 to 133), before `new.txt` is
created at line 135. After that line the edit check makes every case on `$repo` exit 1.

Acceptance check: before touching the script, `bash tests/claude-worktree-busy.test.sh` exits 1
and prints exactly three `FAIL:` lines, all from the new cases: case A's exit (`got '1', want
'0'`), case A's output (the `busy: claude session self0000 ...` line where `''` was wanted), and
case B's message (the caller's id where `busy: claude session aaaa1111` was wanted). No existing
case fails. Save that output for the PR.

## Refusals

- Safety Bypass Flag (`git commit --no-verify`, 2026-11-11): never pass `--no-verify`. A failing
  hook is fixed, not skipped.
- Interfere With Workloads (`pkill -f`, `claude stop` chained with other commands): the test's own
  `trap` ends its fixtures. Stop a background command with `TaskStop`, and never run `pkill`,
  `kill` on a pid you didn't start, or `claude stop`.
- Merge Without Review (`gh pr merge`, a `gh pr view` chained with a merge): the executor never
  merges; the conductor lands.
- Git Destructive (`git push --delete`): push only `ws-d0`, never with `--force` or `--delete`.
- Unexplained refusals of test commands piped to `tail` (2026-11-12): run each test and gate bare,
  never piped.
