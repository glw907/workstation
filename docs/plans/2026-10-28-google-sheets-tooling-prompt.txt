## Prior art to start from

- Google's `clasp` CLI (github.com/google/clasp) handles push, versions, deployments, `clasp run`, and `clasp logs`. `clasp run` needs the script tied to the same Cloud project as the OAuth client, plus an API-executable deployment. Google documents that project switch as a per-script step in the Apps Script editor, which the helper account's browser could do. `clasp logs` reads Cloud Logging, so `console.log`, not `Logger.log`. ## Lessons from the 2026-10-28 gear sheet session

- `gws auth login -s docs,drive,sheets,script` did not add the script scope. Explicit `--scopes` did. A login run with `!` in Claude Code blocks and was interrupted. Run it in the background and hand over the URL with `&amp;` fixed to `&`.
- A `ONE_OF_RANGE` dropdown sent through the Sheets API with a relative range comes back absolute. Set per-row rules one row at a time.
- Simple triggers (`onOpen`, `onEdit`) never fire on API writes. Only a person's open or edit fires them, which is why the browser layer is needed.
- Without `script.processes`, the run history of a script isn't readable, so a failing trigger fails silently.
- A `Range.sort()` on a sheet with a basic filter appeared to do nothing. The fix switched to `sheet.getFilter().sort()`, but nothing has verified it yet.
