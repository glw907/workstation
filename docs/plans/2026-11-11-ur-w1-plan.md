## What changes

`claude-worktree-busy <directory>` keeps its contract: exit 0 and no output when free, exit 1 and
one line when busy, exit 2 on a usage error. Its three checks still run in the same order. Two of
them get narrower.

The session check skips a row whose `state` is `done`, `stopped`, or `failed`. Every other row
whose cwd is in the path stays a hit, including a row with no `state` key, which is how an
interactive session's row looks (M1). The check keeps reading `claude agents --json` with no
`--all`.

The process check skips two command lines, read as an argument list split on NUL bytes:

- The Claude daemon: the first argument's basename is `claude`, and the next two are `daemon` and
  `run`.
- The queue's server: the first argument's basename is `node`, and the second ends with
  `/approval-queue/build`. Later arguments are allowed, since Q1 keeps the command line
  beginning `node <path>/approval-queue/build`.

Every other process with the path in its command line stays a hit. That includes another `node`
process and a `claude` process that isn't `daemon run`.

Out of scope: the hit messages, the edit check, the path-matching pattern at line 35, and every
caller. No `docs/STATUS.md` line changes, because the only line there that names the check is
line 22, inside the conductor's round-report block.

Four traps. The first is a race, and the other three come from the edit check running last.

- A fixture's command line is the test's own until its `exec` lands. A check that runs in that
  window sees no path, so an exit-0 case passes with a wrong script and an exit-1 case fails
  with a right one. Add one helper to the test that reads `/proc/<pid>/cmdline` every 0.05
  seconds, for 2 seconds at most, until it starts with the first argument the case expects, and
  fails the case if it never does. Call it before every `check` that has a fixture process, the
  three existing sleeper cases included.
- `<root>/approval-queue` is a fixture git repo. A fresh untracked file in it is an edit hit, so
  commit its `approval-queue/build` and `approval-queue/build.old` files by path before the
  cases run. Otherwise the two server cases fail on `busy: uncommitted file` with a correct
  script.
- Put every new case that checks `<repo>` before the existing line 57. From line 62 to line 64
  `<repo>/new.txt` is a fresh uncommitted file, so an exit-0 case placed there fails on the edit
  check with a correct script.
- Never run `git add -A` or `git add .` in a fixture repo. It would commit `new.txt`, and the
  case `uncommitted file aged past 60 minutes` would then pass without testing anything.

## Gate runs

Run each gate command bare, as its own Bash call from the worktree, with the Bash tool's
`timeout: 600000`. The default timeout is 120 seconds and the full gate took 185 (M10), so a
call without the longer timeout loses the run.

- Fast lane, after T1 and after T2: `bash scripts/gate.sh --scope-changed`. For the two task
  files it runs 11 legs (M10).
- Full gate, at close: `bash scripts/gate.sh`.

The wrapper waits on a lane lock that every session on the machine shares. On exit 75 run the
same command again, and keep doing so until it prints a `gate exit:` line. Never pipe a gate
into `tail` or `head`, and never poll a log. The new shell code in the test meets `shellcheck -S
warning`, and a new docstring in the script meets ruff's `D` rules, `D401` (an imperative first
line) among them.
